# 升级与降级

本文说明 OptiRoute 的版本策略、升级顺序、降级模式的行为边界，以及回退到旧版本时需要注意的状态

## 1. 版本策略

项目尚未进入 STABLE 版本：

- 不承担旧版本向后兼容义务，协议、配置与 Token 格式可以随版本演进
- 旧格式的兼容代码会尽快移除，而不是长期保留
- 因此跨版本升级前请先确认目标版本对应的文档，不要假定旧配置可以直接沿用

## 2. 升级顺序

按 **Center → Edge → Server Agent → Client Agent** 的顺序逐个替换二进制

这样排序的原因是各角色对控制面的依赖方向不同：

- Center 是控制面权威，先升级它可以让新字段的下发与校验先就位
- Edge 向 Center 注册，后升级的 Edge 面对的是已经认识新字段的 Center
- Server Agent 不连 Center，但 Edge 会校验它的确认帧；先升级 Server Agent 可以让 Edge 拿到带版本信息的确认帧
- Client Agent 只做本地接入与透传，与服务端两侧的协议约定最少，放最后升级对链路影响最小

每个角色升级时都需要重启进程；控制面连接会由 Edge 自动重连，无需手工干预

## 3. 升级期间的状态变化

### 控制面连接

Edge 重启后会向 Center 重新注册。若重启间隔较长，Center 会把该 Edge 记为下线，其节点在整个集群的拓扑中暂时消失，直到重新注册完成

### shared_secret 版本号

Center 进程重启后，`secret` 版本号会从 1 重新开始计数；Edge 在建立新的 WebSocket 连接时调用 `ResetVersion` 清空已接受的版本基准，因此不会把新 Center 实例的低版本推送误判为旧推送而丢弃

需要留意的是：**Center 重启会立即生成一个新的 shared_secret**，过渡期内 Edge 仍可用上一代密钥验签（有效期取两倍 `token_ttl_s`），因此已在途的 Token 不会被立刻拒绝，但超出该过渡期的 Token 会失效

### 拓扑缓存

Edge 配置了 `self.topo_cache_dir` 时会把拓扑与 shared_secret 写入 `topo_cache_<uuid>.json`：

- 升级后第一次成功注册即会刷新该文件，因此通常不需要手工清理
- 缓存文件中的探测项字段（`items`）缺失时，Edge 会按旧缓存处理并为该节点合成一个真实探测项兜底；新格式明确给出空列表时不会回退合成，两种情况在 [FAKE-IP 文档](FAKE-IP_zh-CN.md) 中有说明
- 若新版本的探测项结构发生变化，建议删除缓存文件让 Edge 以全新状态重新拉取拓扑，而不是依赖兜底逻辑

### 日志与文案语言

日志与启动文案默认为 `en-US`，因此升级后原先输出中文日志的部署会看到英文，直到用 `self.lang` 或 `--lang` 指定其它语言：

- 无需改动配置，原有中文文案仍可通过 `--lang=zh-Hans` 或 `--lang=zh-Hant` 取得
- 日志行与配置加载失败、配置校验失败都随同一语言；其中配置加载失败只能用 `--lang`，因为此时读不到 `self.lang`
- 通过 `%v` 或 `%w` 带进日志的 `error` 值保持产生它的那一层的措辞，因此 `protocol`、`util`、`auth`、`edge`、`center`、`agent` 的错误值在英文行里仍会以中文出现
- 未支持或格式非法的标签不会阻止启动：进程以 `en-US` 输出并在标准错误打印一条提示，因此标签写错会出现在输出里而不是被隐藏
- 依赖中文原文匹配日志行的工具需要更新，因为措辞现在来自消息目录

## 4. 降级模式

### 何时进入

Edge 启动时按 `self.center_connect_retry_count` 次重试连接 Center，全部失败后：

- 配置了 `self.topo_cache_dir` **且缓存文件存在且可用**时，加载缓存并进入降级模式
- 未配置缓存目录、缓存文件不存在、或缓存中节点列表为空时，进程以错误退出

降级模式下 Edge 仍会启动探测端口与业务端口，因此仍能对外提供引导与转发

### 一个前提条件：缓存中需要有 shared_secret

降级模式要签发 Token 就必须有 shared_secret。该密钥随控制面推送写入缓存，因此：

- 该 Edge 曾经以正常模式连接过 Center 时，缓存中会有密钥，降级模式可以签发 Token
- 缓存中没有密钥时，引导流程会在签发处失败，日志中会给出「缓存中无 shared_secret」的提示；此时客户端会等待超时而不是拿到 Redirect

### 何时退出

降级模式下 Edge 在后台按指数退避重连 Center，重连并注册成功后切回正常模式，随后重新拉取拓扑并刷新缓存

### 降级模式下的行为差异

| 项目 | 差异 |
|---|---|
| 拓扑来源 | 本地缓存，可能落后于集群当前状态 |
| 带宽惩罚乘数 | 由控制面下发，降级模式下收不到拓扑响应，因此该乘数保持为 0，选路不施加带宽惩罚 |
| 版本与客户端信息上报 | 无控制面连接，上报不会送达 |
| FAKE-IP 列表更新 | 仍会尝试上报，但消息留在降级模式下不被消费的写队列中，不会送达 Center |

## 5. 回退到旧版本

回退前需要确认两件事：

1. **配置兼容性**：新版本引入的配置项在旧版本中会被忽略，而新版本中取值语义变化的字段（例如从标量改为可区分「未配置」与「显式 0」的表示）在旧版本中按旧语义解读，因此回退时应使用与旧版本匹配的配置文件，而不是直接沿用新配置
2. **缓存文件格式**：缓存文件由 Edge 写入也由 Edge 读取，回退后若旧版本无法解析新格式，删除 `topo_cache_<uuid>.json` 让 Edge 重新拉取是更稳妥的做法

回退顺序与升级相反：**Client Agent → Server Agent → Edge → Center**

回退期间同样需要重启进程，且同样会经历第 3 节列出的状态变化
